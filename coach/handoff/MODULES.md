# Report plan format and the blocks you can choose

A plan is ONE JSON file. Allowed top-level fields: `report`, `agenda`, `moments`, `summary`, `notes`, `analyst`. Anything else is rejected.

```
{
  "report":  {"subtitle": "30 games · compared with the other players in those same games"},
  "agenda":  "Keep: ...\n\nWork on: ...\n\nRe-check next time: ...",      // required, short preview, paragraphs split by blank line
  "moments": [ <Teaching Moment>, ... ],                                   // required, 2 to 4 recommended
  "summary": {"covered": [..], "watch": [..], "retest": [..]},              // one short line each
  "notes":   {"key": "longer caveat text"},                                 // optional; cite in text as [[note:key]]
  "analyst": {"open_questions": ["..."]}                                    // shown on the Analyst Desk
}
```

## Teaching Moment
```
{
  "id": "unique-slug",
  "intent": "ACTION" | "UNDERSTAND" | "REINFORCE" | "WATCH",   // ACTION: change something. UNDERSTAND: explain a pattern.
                                                                // REINFORCE: keep doing it. WATCH: keep an eye on it.
  "title": "...",            // required, the lesson in plain words
  "question": "...",         // required, the player's question in first person ("How often am I ...?")
  "blocks": [ <Block>, ... ],// required, at least one
  "takeaway": "...",         // required, ONE thing to do or keep
  "analyst": {"alternatives": ["other explanations"], "limitations": ["what the data cannot say"]}
}
```

## Block
`{"layout": ..., "text": "...", "module": {...}}` with exactly these rules:
- `text_above` and `side_by_side`: need both `text` and `module`.
- `text_only`: `text`, no module.
- `module_only`: `module`, no text.
Text may use blank lines for paragraphs. Plain text only (no HTML/markdown).

## Modules (the `type` field picks one)
| type | Fields | What the software draws |
|---|---|---|
| `FindingCard` | `finding` (id from findings_shortlist.json), `caption` | The player's rate against the comparison group as bars, with the software's verdict sentence and a "How is this calculated?" fold-out. Use this to show HOW OFTEN something happens. Works for any finding, with or without examples. |
| `KeyMoments` | `finding`, `title`, `picks`: list of `{example: <index into that finding's examples>, note: "Coach's read"}` (1 to 6) | An accordion of real rounds. Each has "What happened (from the demo)" facts generated by software, an interactive 2D replay of the round on the map, your note, and a full kill list. Only findings that have `examples` can be used. The software chose the examples and states why; you choose which to show and write the note. |
| `MetricPair` | `title`, `left`, `right` each `{metric, caption, tone}` | Two big-number cards. `metric` = an id from digest.json `metrics`. tone: neutral / good / bad. |
| `MetricCluster` | `title`, `metrics`: 2 to 4 of `{metric, caption, tone}` | 2-4 number cards. |
| `ContextBreakdown` | `title`, `measure`: opening_balance / kd / adr / utility_damage, `highlight`: list of map ids like "de_mirage" | Bars per map. |
| `SituationContrast` | `title`, `left`, `right` each `{demo, round, label, why}` | Two rounds side by side with software-written timelines. `demo` = a folder name in data/batch. |
| `EventTimeline` | `title`, `situation` `{demo, round, label, why}` | One round's kill timeline. |

Not available (do not ask for them in the plan): dashboards, free-form charts, custom replays without a finding, economy views. Mention needs in review.md.

## Numbers in text
The validator scans every text field. Digits >= 10, decimals or percentages must exist in the digest or the usable findings. Prefer showing numbers with a FindingCard/Metric block. Words are not scanned, but rule 1 in RULES.md still applies to them.

## Choosing findings
- `findings_index.txt` lists the 199 findings that have enough cases, strongest first: status (credible / leaning / unclear / no_difference), id, count, player rate vs comparison rate, q (after correcting for the number of checks), whether both interleaved splits of the games agree, and how many replay examples exist.
- `credible` = survives the multiple-checks correction. `leaning` = exploratory. `no_difference` = a real null result worth a short mention. `unclear` = not enough to tell.
- Finding ids look like `fight.habit.s_phase.first 25 s`, `value.first_death`, `trading.converted`, `fight.result_vs_own_level.s_phase.after 60 s`. Copy them exactly.
- Kinds: `habit` = how often the player is in a situation compared with peers (a style/position fact, not a result). `result_vs_everyone` / `result_vs_own_level` = win rate in a situation. `value.*`, `trading.*`, `clutch.*` = round-level measures.
