Download PlayerStudy Coach Handoff v0.1

This version is intentionally restricted to:

one analyzed batch → one player → one Player Study

There is no longitudinal coaching, previous-batch comparison, coaching-memory system, improvement/regression tracking, Analyst Desk output, or Personal Coaching loop in this experiment.

The package gives a completely fresh AI two distinct jobs:

    Interpret the batch. It reads the analyzed v7.7 files, verifies integrity/capabilities/player identity, computes the useful batch-level evidence, identifies up to five genuinely supported findings, selects representative situations, distinguishes observation from interpretation, and outputs coach_analysis.json.

    Build the Player Study. It receives that completed analysis and is no longer allowed to rediscover findings. It chooses from a finite module registry, writes the player-facing explanation, and outputs player_study_report.json.

That distinction is important. It lets us separately judge “Was the coach intelligent?” and “Did the report system present that intelligence well?”

The package contains:

    PASTE_TO_FRESH_AI.md — essentially the instruction you can hand directly to a completely fresh AI.
    00_TEST_SCOPE.md — explicitly locks this experiment to one batch and one Player Study.
    01_COACH_INTERPRETATION_PROMPT.md — the coaching-analysis prompt, derived from the existing strong schema-3 coaching prompt but stripped of longitudinal obligations.
    02_BUILD_PLAYER_STUDY_REPORT_PROMPT.md — the separate report-building prompt.
    contracts/coach_analysis_v1.schema.json — what the coach must produce after analyzing the batch.
    contracts/player_study_module_registry_v1.json — the authoritative list of modules the AI is allowed to use.
    contracts/player_study_report_v1.schema.json — the reproducible final report contract.
    scripts/validate_player_study.py — local validator using only standard Python.
    minimal example analysis/report files that already pass that validator.
    the older source contracts/prompts under source_material so we retain traceability without making them runtime authority.
