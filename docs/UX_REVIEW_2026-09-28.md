# UX / analytical review of the first MIMY report (2026-09-28)

Source: an outside review supplied by the owner, to be **considered, not obeyed**. Each point below has
my verdict. "Verified" means I measured it on the actual page. Status: accept (do it), adapt (do a
version of it), defer (later), or decline (with reason).

## Trust and analytics
| Point | Verdict |
|---|---|
| Rifle speed pair (61 vs 84) compares two different moments and is coloured good/bad | **Accept.** Verified in our own notes: kill speed is measured at the player's first shot, death speed at the enemy's. Until both are measured at the same event, show neutral, unpaired, worded as a question. Longer term: measure both at one event. |
| Survival after an opening kill shows "20 of 20 won" but omits "21 of 44 won when you died later" | **Accept. My omission.** Always show the comparison pair, plus the confound, plus time-to-next-death before claiming "immediate second fight". |
| Raw opening kills/deaths compared across maps with different round counts | **Accept.** Show win share and n per map, not raw bars on one scale. |
| "First fights" is really "first kill of the round" | **Accept.** Rename to "opening kills / opening deaths". |
| Examples labelled "typical" without a selection method | **Accept.** Remove "typical" until a representativeness method exists. |
| "Strength" claimed with no benchmark | **Accept, and it is bigger than wording.** See ADR-012: no "strong/weak/normal" without a stated baseline. |
| Caveats that change the advice hide behind disclosures | **Accept.** Rule: if a limit could change what a reasonable player does, it sits next to the advice. |
| Confrontational or over-strong wording ("map problem or a you problem", "model of how you like to fight", "keep doing it the same") | **Accept.** |
| Grenade section infers cause too quickly; title should say HE + fire damage | **Accept.** |
| Red/green implies verdicts on unsettled measures | **Accept.** Colour only where the measure is clearly good or bad. |
| No single priority; four findings weigh the same | **Accept.** Matches the owner's critique: one or two priority actions, observations clearly separate. |

## Length and structure
| Point | Verdict |
|---|---|
| Report is very long (verified: ~11,000 px on a phone) with no navigation | **Accept.** Short "what to do" at the top, each item linking to its evidence; section navigation. |
| Agenda, takeaways and summary repeat each other | **Accept.** Merge into one top summary. |
| Round examples show the whole kill feed | **Accept.** Owner independently said the same. Show only the decisive moment; full round behind a control. Real answer is the map replay (roadmap). |
| Too many nested boxes | **Adapt.** Fewer containers; keep one strong treatment for the main instruction. |
| Footnotes poor at this length; speed caveat too important for a footnote | **Adapt.** Important caveats inline; footnotes only for minor ones. (Owner agreed two-level notes earlier, marked Leaning.) |
| Repeated "How is this calculated?" everywhere | **Adapt.** Show n and the one needed caveat; link to the Analyst Desk metric. |

## Accessibility and responsive
| Point | Verdict |
|---|---|
| Analyst Desk overflows on a phone | **Accept. Verified: 759 px wide on a 390 px screen.** Redesign as stacked rows; I only tested phone overflow on the Player Study tab, which was my gap. |
| UI text as small as 11.5 px | **Accept. Verified.** Minimum 13 px. |
| T-side orange fails contrast | **Accept. Verified: 3.64:1 on white, 3.11:1 on the highlighted row (AA needs 4.5:1).** Darken in light mode. |
| Tabs lack ARIA wiring, keyboard arrows, deep link; scroll resets | **Accept.** |
| Whole Analyst Desk unreachable without JavaScript | **Accept.** Content must exist without script. |
| Bars lose their plot area on phones | **Accept.** Use compact rows like "Cache 15-4 79% (n=19)". |
| Prose too wide | **Accept.** ~70 characters. |
| Print shows both tabs, closed disclosures, large keep-together blocks | **Accept**, lower priority. Separate "player report" and "with analyst appendix". |
| Exports hidden at the bottom; base64 links heavy | **Accept**, lower priority. |
| Header: duplicate "Player Study", vague "Complete for this study", no date | **Accept.** State "30 of 30 games passed checks (0 excluded)" and the report date. |
| UUID game list | **Accept.** Human labels first (map, order, score); id secondary. |
| Analyst Desk columns (Value/Count/Out of/Id) awkward; blank cells | **Accept.** Redesign around Metric / Result / Sample / Definition. |
