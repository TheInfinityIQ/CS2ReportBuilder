# Skybox personal demo sync

Open **Tools & setup → Skybox demos**, paste a **FACEIT profile link**, choose the **Number of demos** (1–100), then click **Upload to Skybox**. These are the only controls in this panel. Download/upload progress stays in the existing Toolbox console. The chosen batch count is saved (default 10 when unset); the download method is always Automatic.

The action automatically opens and pairs the normal browser companion, checks all Skybox inventory pages and pending uploads, passes a multi-match plan to the existing FACEIT downloader, then uploads its completed indexed files. Known local files and cached hashes are reused. Duplicates/unavailable files trigger a smaller refill batch if required. No analysis is run.

Automatic acquisition uses the same `downloads.acquire_plan` routing as Download demos: direct API access where available, otherwise the existing browser companion and configured downloads folder. Demos always go under `C:\Program Files (x86)\Steam\steamapps\common\Counter-Strike Global Offensive\game\csgo\replays`, using the existing map → player folders, score/date/map filenames, archive validation, checksum reuse and replay index. Existing files are preserved. Files are limited to 1 GiB because Skybox's browser hash worker loads the full file into memory.

The existing **CS2 Toolbox Browser Companion 1.1.2+** must be enabled in the normal browser; the installed companion is connected automatically without a separate inventory or setup action. Skybox sign-in stays in that browser. Keep its tabs open and complete any required sign-in or site verification there. Browser extension installation and sign-in cannot be performed silently. The companion covers FACEIT, HLTV, Skybox and a paired localhost job.


Duplicates use Skybox's BLAKE3 identity, including legacy 16-character IDs. Processed inventory requests only match hashes; premium original-demo URLs are not requested. Pending upload names may identify a known single-map match; otherwise files are checked by hash. The companion refreshes inventory before each upload, tries Skybox's existing-hash flow, and uses its presigned storage upload only when both native hash lookups report not-found. This uses observed private website operations, so website changes can require an update. Unexpected pagination or API responses stop the job.

**Accepted does not mean processing completed.** Check the normal Skybox library for processing results. Sync results and account/player-scoped journals are under `data/.desktop/skybox`. Lost upload receipts are marked uncertain and never resent automatically. Review these in Skybox before explicitly clearing an individual journal attempt; do not delete the journal as a routine retry step.
